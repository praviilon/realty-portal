# Smart Realty — деплой и обновление на хостинге (Timeweb)

Этот файл описывает текущий процесс: как проект обновляется на сервере после того, как изначальный деплой (Фаза 0) уже сделан и `/admin` + `/catalog` работают.

## Как теперь идёт разработка

- Код пишется и тестируется в облачной среде (Claude), где настроено то же окружение, что и на сервере (PHP 8.4, Composer, Node).
- После каждого проверенного эпика/фикса изменения коммитятся и пушатся напрямую в GitHub, в репозиторий `praviilon/realty-portal`, ветка `main`.
- На сервер изменения попадают вручную, когда вы решаете обновить продакшн — командой `git pull` и парой команд `artisan` (см. ниже). Автоматического деплоя на каждый push нет — это осознанно, чтобы непроверенные изменения не улетали в продакшн сами.

## Обновление сервера (когда в GitHub появились новые коммиты)

Подключитесь к серверу (SSH-консоль в панели Timeweb или обычный SSH-клиент) и выполните:

```bash
cd ~/realty-portal
git pull origin main
composer install --no-dev --optimize-autoloader   # только если менялся composer.json/composer.lock
php artisan migrate --force                         # только если добавлялись новые миграции
php artisan optimize:clear
```

Если во время работы вы вручную правили какой-то файл прямо на сервере (как было с `AdminPanelProvider.php`) и не сообщили об этом — перед `git pull` стоит проверить:

```bash
git status
```

Если там есть незакоммиченные изменения — сообщите мне, что именно правили, чтобы я перенёс это в основной код, иначе `git pull` может отказаться применяться (конфликт) или ваша ручная правка потеряется при следующем обновлении.

## Важное предостережение: `filament:install --panels --force`

Эту команду **не нужно** запускать повторно на уже работающем сервере. Она пересоздаёт `app/Providers/Filament/AdminPanelProvider.php` заново из шаблона Filament — и если файл уже был кастомизирован (например, содержал `->default()`, свои пути `discoverResources` и т.д.), все эти правки затираются шаблоном. Именно так один раз уже терялась строка `->default()` и админка переставала пускать через `make:filament-user`.

`filament:install --panels --force` нужен только один раз — при самом первом деплое на чистый сервер, где панели ещё не существует. Для всех последующих обновлений формы панели (новые ресурсы Filament, новые виджеты и т.д.) код уже придёт готовым через `git pull` — пересоздавать провайдер не требуется.

## Первоначальная настройка (уже выполнена, оставлено для истории)

Исходные шаги первого деплоя — от создания приватного репозитория до первого `php artisan migrate` — описаны в истории переписки с Claude. Кратко: `composer install --no-dev`, `.env` с `DB_*`/`APP_URL`/`YANDEX_MAPS_API_KEY`/`SMARTCAPTCHA_*`, `php artisan key:generate`, `migrate --force`, `storage:link`, `filament:install --panels --force` (один раз), document root на `~/realty-portal/public`, `make:filament-user` + ручная простановка `role = admin` через tinker.

## Ключи API, которые всё ещё нужно проверить/дозаполнить в `.env` на сервере

- `YANDEX_MAPS_API_KEY` — developer.tech.yandex.ru (JS API 3.0 + HTTP Геокодер)
- `SMARTCAPTCHA_SITE_KEY` / `SMARTCAPTCHA_SERVER_KEY` — cloud.yandex.ru

После добавления/изменения — `php artisan config:cache` на сервере.
